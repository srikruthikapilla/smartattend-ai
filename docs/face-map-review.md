# Face flow and blank-map fixes

Map tiles were blocked by the production Content Security Policy: the component used server.arcgisonline.com but img-src did not permit that origin. The policy now permits that specific host. The component falls back to OpenStreetMap on tile errors, shows an error/retry control if that also fails, bundles marker images locally, and observes container size changes so modal maps render correctly.

Chromium verification used the production CSP: all four visible tiles loaded, no tile CSP violations occurred, and forced primary-provider failure successfully loaded OpenStreetMap. Screenshot: ../scratch/map-fixed.png. Deploy the frontend container to apply both the JavaScript and Nginx policy changes.

Face fixes cover real GPS acquisition (no fabricated classroom coordinates), complete liveness telemetry on manual submission, stale async scan cancellation, serial multi-frame enrollment, cache publication only after database commit, database-authoritative revocation, finite/nonzero face vectors, minimum open/closed/reopen blink sequences, shared model loading, honest enrollment-save errors and passkey fallback without dummy face descriptors. Disabling geofencing no longer leaves the saved distance undefined. Revoking a face by UUID also removes its hall-ticket registry entry.

Validation uses synthetic face vectors and blink signals, mocked database sessions and a real browser loading the bundled face models. Tests cover same/different vectors, invalid values, malformed blink sequences, successful face attendance, rejected mismatches, failed liveness, passkey fallback, geofence-disabled attendance, stale-cache rejection and failed enrollment persistence. No physical webcam, real person's face, SMTP delivery, or production database was exercised. Recognition thresholds were not claimed to be calibrated by this test; actual false-accept/reject rates require representative consented samples. Client-supplied face/GPS telemetry is not hardware attestation.
